# シミュレーションの中身

数字をいじる前にここを読むこと。`npm test` と `npm run timecheck` が
ここに書いた性質を機械的に見ている。

## 1. コースの幾何（`src/sim/course.js`）

1 周をオーバル（直線 ＋ 半円のコーナー）で近似し、**ゴール板を周回位置 0** とする。
距離 D のレースは `start = (L - D % L) % L` から始めて、走破距離が D になった
ところでちょうどゴール板に戻る。

この定義にしておくと、発走位置が自動的に正しくなる。
東京芝 2400m は 1 周 2083m なので `start = 1766`、つまり正面スタンド前からの発走。
実際の東京優駿と同じ場所になる。

### 輪が閉じる条件

180 度のコーナーは進行方向の変位を持たない。したがってオーバルが閉じるには

```
（ゴール板 → 1 コーナー）＋（4 コーナー → ゴール板） ＝ 向正面
```

でなければならない。JRA の公表値（1 周距離・直線距離・向正面）はこれを満たさないので、
**直線距離だけを厳密に守り、残りを均している**。
結果のコーナー半径は 120〜155m になり、実際の日本の競馬場と同程度に収まる。

### 持っているデータ

| 場 | 1 周（芝） | 直線 | 高低差 | 回り |
|---|---|---|---|---|
| 東京 | 2083m | 526m | 2.7m | 左 |
| 中山 | 1840m | 310m | 5.3m | 右 |
| 阪神 | 2089m | 474m | 2.4m | 右 |
| 京都 | 1894m | 404m | 4.3m | 右 |
| 中京 | 1706m | 413m | 3.5m | 左 |
| 新潟 | 2223m | 659m | 0.8m | 左 |
| 札幌 | 1641m | 266m | 0.7m | 右 |
| 函館 | 1627m | 262m | 3.5m | 右 |
| 福島 | 1600m | 292m | 1.9m | 右 |
| 小倉 | 1615m | 293m | 3.0m | 右 |

坂は「残り距離」で持つ。中山は残り 180m から 22‰ の上り、
小倉は 4 コーナーから下り、京都は直線が平坦で 3 コーナーに坂（`cornerGrade`）。
新潟外回りは完全な平坦で、だから上がりが異常に速くなる。

内回り／外回りの別はまだ持っていない（外回り相当の数値を使っている）。
新潟芝 1000m だけは周回しない別トラックとして扱う。

## 2. 馬（`src/sim/horse.js`）

### 能力の二層

- `pot` — 潜在能力。生まれた瞬間に決まる上限。**画面には一切出さない**
- `cur` — 現在値。調教と出走で `pot` に近づく。画面に出る評価はこれ

発揮される力は `cur × 成長率 × 仕上がり × 調子 × (1 - 疲労)`。
成長率は年齢と成長型（早熟・普通・持続・晩成）で決まる。
早熟は 3 歳で頭打ち、晩成は 5 歳で最大。
これがクラシックと古馬 GI の住み分けを作っている。

### 適性

- **距離** — 最適距離と許容幅。`1 - 0.34 × (差 / 幅)^1.5`。
  急峻にすると、頭数合わせで長距離 GI に回された馬が 3000m を 4 分台で走る
- **馬場** — 芝 / ダート
- **馬場状態** — 良 / 重（稍重・不良はその間を補間）

レースではこの三つを、それぞれ帯に写してから掛ける。
素のまま掛けると、どれも中くらいの普通の馬が 0.86 まで落ちて、
GI が実際より 10 秒以上遅くなる。

### 気性・丈夫さ・底力

- **気性** — 低いとゲートで出遅れ、道中で掛かる（余力を無駄に使う）
- **丈夫さ** — 故障の抽選に効く。重い故障は治っても潜在能力を削る
- **底力** — 残り 400m の粘り。GI ほど効く

## 3. レース（`src/sim/race.js`）

0.1 秒刻み。モデルの骨格は四つ。

### (1) 最高速の差は小さい

```
vMax = (17.1 + 2.75 × スピード) × 適性 × 馬場 × 騎手 × 斤量
```

スピード 0 の馬でも 17.1 m/s（約 62km/h）出る。
未勝利馬と GI 馬の時計差は実際の競馬でも 3〜5% しかなく、
ここを広げると世界が壊れる。勝負を分けるのは余力の側。

### (2) 道中は馬群がひとつの速度で動く

先頭が巡航速度を決め、後続はそれに合わせる。脚質の違いは
**「先頭から何メートル後ろに居たいか」** だけ。16 頭立て 2000m で隊列は 30m 前後に伸びる。

巡航速度の比率は距離が伸びてもあまり下がらない
（3200m の 1000m 通過 62 秒は 2400m とほぼ同じ）。
長距離が楽にならないのは速度ではなく余力の側で決まっている。

逃げたい馬が増えるごとに巡航速度が 1.9% 上がる。
**展開はほぼこれだけで決まる。** ハナ争いが起きれば前が止まり、差しが届く。

### (3) 余力（HP）

```
消費 = 基礎 0.45/秒
     + 1.2 × (速度 - 巡航域)²        巡航域 = vMax × 0.86
     + コーナー（曲率 × 速度）
     + 上り勾配
   × 隊列位置の係数（先頭 1.15 〜 30m 後方 0.87）
```

最後の項が肝。先頭は自分でペースを作るぶん損をし、後方で我慢した馬は脚が溜まる。
この非対称がないと、先に行った馬がそのまま残って逃げ馬だけが勝ち続ける。

余力が減ると最高速が連続的に落ちる（`1 - 0.15 × (1 - 残量)^3.5`）。
指数を高く取っているので、半分あるうちはほとんど落ちず、尽きかけてから一気に効く。
空になってからは 1 秒ごとにさらに落ち、最低でも 85% で止まる。

**この帯を広げてはいけない。** 実際の 2000m 戦は最下位でも勝ち馬の平均速度の
95% 前後で走っていて、着差にして 5〜8 秒に収まる。
能力・適性・バテを合わせた最高速の開きが 15% を超えると、
格負けした馬が 40 秒離される絵になる。適性の差は速度ではなく余力の側に置いている。

### (4) 進路

横位置は**内ラチからのメートル**で持つ。コーナーで `off × 曲率` だけ余計に走る。
内ラチから 5m 外を半径 150m のコーナーで回れば、その区間を 3.3% 損する。

前方 2〜5m・横 1.8m 以内に馬がいれば詰まる。
体半分しか前に居ない馬は「並んでいる」のであって壁ではない。

**ゲートを出て最初の 80m は進路判定を切る。** 出た瞬間は馬群が横一線で、
前が詰まるという状態が無い。ここで通常の判定を当てると、わずかに前に出た馬の
速度に後ろが連鎖的に引きずられ、最後方の馬が 25 秒もゲート前に取り残される。
追突時の速度に 1 未満の係数を掛けるのも同じ理由で駄目で、
最低速度との組み合わせで「前の馬より必ず遅い」状態が固定され、馬群全体が貼り付く。
空いている側（外を優先、なければ内）へ 1.25 m/s で持ち出し、
**両側が埋まっていれば前の馬に合わせて待つ**。

「詰まったら必ず外へ」にすると、16 頭が走路いっぱい（31m）に広がったまま
前後に詰まって全馬が停止する。追突時の減速を「前の馬 × 0.95」にするのも駄目で、
連鎖して最後尾が半分の速度になる。

### 出力

着順・走破時計・着差（馬身）・上がり 3F・コーナー通過順位・
ペース判定（前半後半の時計差）・一言回顧、そして**走行ログ**。

走行ログは 0.2 秒ごとの位置・横位置・速度を `Float32Array` に詰めたもの。
3D はこれを再生するだけで、結果を変えられない。

## 4. 血統と配合（`src/sim/pedigree.js`, `breeding.js`）

### インブリード

仔を基準に 5 代までの共通祖先を検出する。父自身・母自身も祖先として数えるので、
父が母の祖先に入っていれば 1×N になる。

| 形 | 効き | 危うさ |
|---|---|---|
| 3×4 | 1.00 | 0.22 |
| 3×3 | 0.92 | 0.46 |
| 4×4 | 0.80 | 0.14 |
| 2×3 | 0.72 | 0.72 |
| 2×2 | 0.55 | 1.00 |
| 5×5 | 0.30 | 0.02 |

効きは祖先の格（能力と現役成績）で重み付けされる。重ねすぎは頭打ち。
危うさは**丈夫さと気性**に出る。能力だけ上がる都合のいい配合は無い。

### ニックス

父系 × 母父系の相性。世界生成時に系統ペアごとの隠し値が決まっていて、
その組み合わせの産駒が 12 頭走るまでプレイヤーには「？」と表示される。
遊んでいるうちに「流行の配合」が自然に生まれる。

### 平均への回帰

```
仔の能力 = lerp(両親の平均, 0.42, 0.26) + 正規乱数(sd = 0.095 + 平均 × 0.075)
           + インブリード効果 + ニックス
```

項目ごとに別々に抽選するので、父のスピードと母のスタミナ、という
組み合わせが出る。回帰項がないと、数十年で全馬が上限に張り付いて世界が壊れる。

分散は親の能力が高いほど大きい。名馬の仔ほど大物も駄馬も出る。

## 5. 競馬界（`src/sim/world.js`）

### 生成

```
創始世代（種牡馬 18・繁殖牝馬 140、親なし）
  ↓ 56 年ぶん、毎年産駒を作って 4 年後に次の種牡馬・繁殖を選抜
現役世代（2〜7 歳、各 600 頭前後）
  ↓ 誰の祖先でもない馬を捨てる
約 4500 頭の競馬界
```

生成は 0.2 秒ほど。5 代血統表の埋まり率 75%、1 頭あたり平均 3 のインブリード。

2 歳以上には「紙の上の戦績」を与える。でないとゲーム開始時に全馬が無印になる。
ただし**開始年ぶんは走らせない**（まだ行われていないレースが戦績に並ぶため）。

### 週送り

1. 馬場状態と天候を決める（`(シード, 年, 週)` から導く）
2. その週の番組を作る（同上。先の週を何度覗いても変わらない）
3. NPC が出走申し込み → 騎手手配 → レース実行
4. 結果を戦績・賞金・レコード・リーディングに反映
5. 全馬の調教・放牧・回復
6. 年末ならリーディング集計・引退・配合・出産・加齢

### NPC の使い分け

馬は「自分のクラス」ではなく「狙うべきクラス」でレースを選ぶ。
オープン以上は収得賞金と能力で行き先が分かれ、3 歳春は素質だけで決まる。
勝ち数だけで決めると、強い馬が永遠にオープン特別に留まって GI が空になる。

重賞は頭数が足りなければ条件を満たす馬を補充して必ず成立させる。
補充は「強い順」ではなく「このレースに向く順」。
距離適性を無視すると菊花賞に 1600m 馬が並ぶ。

プレイヤーが登録したレースも必ず成立させる。
番組に載っているのに「相手が集まらなかったので中止」ではプレイヤーは何もできない。

## 6. 3D（`src/render3d/`）

走路は `course.js` の幾何から組む。**計算と絵が同じ形を使う**のが要点。
標高は勾配表を 1 周ぶん積分した表から引く（頂点ごとに積分しない）。

馬の脚の位相は**速度ではなく走行距離**で進める（1 完歩 7m）。
こうすると止まりかけた馬の脚もちゃんと止まり、滑って見えない。

カメラは 5 つ。中継（内馬場のカメラ車）・並走・騎手・俯瞰・ゴール前。
騎手視点では自分が乗っている騎手を非表示にする（ヘルメットで画面が埋まるため）。

## 7. セーブ（`src/sim/save.js`）

`Map` と `Set` を配列に落とすだけの素直な変換。
乱数の状態（4 つの整数）も保存するので、**ロード後の週送りが完全に一致する**。

小数の丸めはしない。4 桁に丸めると 15% 縮む代わりに、
ロードした世界が元とわずかにずれ、同じ週を進めたとき 2 割のレースで勝ち馬が変わる。
代わりに空配列と null を書かないことで縮めている。

保存先は IndexedDB。localStorage は 5MB 前後で上限に当たるが、
この世界のセーブは数年で 10MB を超える。
一覧表示用のメタ情報だけ localStorage に置いている。

年末には、誰の祖先でもなくなった馬と、古い戦績の細部（時計・回顧文）を捨てる。
放っておくと 10 年でセーブが数十 MB になる。
